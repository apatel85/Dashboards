## Decisions (standing — don't re-litigate)
- **No API key in the app, ever.** The Gemini key is a server-side secret. Chain: GitHub secret `GEMINI_API_KEY` → workflow `voiceflow-polish-deploy.yml` → Supabase function secret → Edge Function `voiceflow-polish` → Gemini. - iOS out of scope. English first. Flutter pinned 3.50.0 (Dart 3.14).
- Golden fixtures live in `packages/core/test_fixtures/formatting/<profile>/cases.json`.

## 2026-11-15 — 0.7.5: hang fixes, press-and-hold style chooser — DONE (automated)
- Owner reported: after some use the button hangs (stays solid; tapping it opens settings), and asked for press-and-hold on the button to choose the style. Also attached "Dictation App Conversion Spec (Final)" (52 pp.) - its stages are being done in section-15 order in later entries; this entry is only the hang and the chooser.
- **Hang - cause NOT reproduced** (no device/logs here). Found by reading the code, each a plausible cause of "after some use": (1) `SherpaSttEngine.unload()` killed the decoder isolate right after sending `close`, so `recognizer.free()` never ran, and `ImeEngine.destroy()` (idle unload after 5 min) never asked it to - native model memory (~480 MB) leaked on every unload/reload; (2) `transcribe()` waited for the decoder with no timeout; (3) a failed Dart start-up was cached forever (`backend ??=`), so every later call failed and the button treated that as "model not ready" and opened the app; (4) cold-engine calls retried on separate timers, so audio chunks could overtake `streamStart`; (5) the button used a possibly stale `modelReady` and opened the app at once; (6) `streamEnd` had no ceiling, so a silent engine left "working" forever; the mic being taken by a call left it "listening" forever.
- **Fixes:** decoder frees the model and acknowledges before the isolate is killed; `ImeEngine.shutdown()` unloads first, then destroys; decoder timeout (30 s + audio length); start-up failure no longer cached; `DartBridge` queues calls behind a ping so order is kept and supports a per-call timeout; `streamEnd` 90 s ceiling then a fresh engine; mic loss ends the dictation with what was said; the button re-reads status before sending anyone to Settings, sends accessibility problems to Accessibility settings, and a tap while "working" abandons it.
- **Chooser:** press and hold the idle button opens a small list (not focus-stealing) next to it: Casual / Business / Professional / AI prompting, current ticked for the app being typed into (`status` now takes `packageName`); picking saves per app (or as the default when no app is known). Hold while listening still cancels.

- **Cause of the "stopped recording" report:** the Android keyboard hard-stopped after 28 s (`autoStop`) and the speech engine only ever took one clip of about 30 s. Windows had a similar cap. Fix: `LongDictationSession` (core) takes audio as it streams, cuts at a pause (after 8 s of speech; forced at the quietest or shortest-pause point between 20-24 s), transcribes each piece while you keep talking, and joins them. `DictationService.maxDuration` is now null by default. Core tests cover 8-minute and cancelled sessions. Not measured on a real voice: the joins at forced cuts (a word spanning a forced cut can be split).
- **Android is now a floating button, not a keyboard:** `FloatingService` (microphone foreground service + overlay button), `VoiceFlowAccessibilityService` (types into the focused field with ACTION_SET_TEXT, refuses password fields, "scratch that" restores the previous text, clipboard if no field is focused), `BubbleView`, audio streamed to Dart through `streamStart/streamChunk/streamEnd/streamCancel`. `VoiceFlowIME`, `KeyboardUi` and the keyboard setup steps are gone. The E2E seam is now a broadcast receiver that exists only in the `e2e` flavor. **Dropped on purpose:** the keyboard's pack suggestion chip and undo button (packs are switched in the app; undo is the "scratch that" command). **Not done:** restoring the button after reboot; hold-to-talk.
- **Tone:** the four profiles now differ by a `register` (casual keeps slang; business expands it and says Hi; professional also drops filler/intensifiers, uses "thank you", no "!"; prompt is directive). Golden cases added for each. Known flaw left visible: "its" is not turned into "it's".
