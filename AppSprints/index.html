Start a research sprint

Answer a few questions about the app or website you want. The agent does the research — what users call things, how they solve it today, the closest competitors, how it should work on every screen size — and brings back a one-page Research Receipt for you to approve before any design starts.

How it works
  1. Fill in this form (about 2 minutes). Leave anything blank if you do not know it.
  2. Press Build my brief, then Send to GitHub — it opens a prefilled issue for you to submit under your own GitHub login. No password or key is stored here.
  3. The watcher files it into the sprint folder, runs the research, and posts your Receipt in the App Sprints chat. Copy-and-paste in the chat still works if you prefer it.
  4. You say “looks right” or correct one line — only then does design start.

1Name this sprint

One name per request. It becomes the folder name, so keep it short and use only lowercase letters, numbers, and dashes.

Example: tradedesk-revamp-2026-11-12

2Who is it for?

These three answers change the follow-up questions — and the design. Pick one in each group.

3The five questions

“Don’t know” is a valid answer. Leave anything blank and the agent fills it in from research — and flags it as an assumption for you to check.

One sentence. This one is required.

Tell us what we are building, in one sentence.

One line, in plain words. Example: a parent on her phone.

The single most important thing they must finish in it.

Brand rules and must-avoids. Example: never ask for payment, never use cricket jargon.

4For you or your team

Shown because this is for you or a known group, not the public.

A spreadsheet, a WhatsApp thread, memory, another app?

4For the public

Shown because strangers will arrive at this. First impressions and trust decide whether they stay.

A link you share, a search, social media, word of mouth?

Who runs it, that it is safe, that it is real?

4Each role

Shown because there are several kinds of users. One block per role — the agent needs to know what each role does and what each role must never see.
