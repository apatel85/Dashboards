Skill Library — redesigned

One Library per sport, built like Programs: a grouped landing that expands, a library page that is the read view, and a full-page sub-skill editor — with the same create, edit and publish shells programs use. Underneath, one Pathway per sport in Academy settings; each library is a Skill tree (renamable labels) and a Drill bank; each sub-skill has a Stage map with at least one assessed stage.

Four settled decisions (do not re-litigate)

  1. One sub-skill per skill, with a Stage map. Assessed rows carry their own pass standard; Introduce and Revisit rows carry none; at least one Assessed row, pre-created.
  2. One pathway per sport, in Academy settings. Libraries inherit it read-only; no per-library override in v1.
  3. Assessment definition captured now, per Assessed stage — what the coach checks, pass standard, scoring type, points. Recording results per athlete is later.
  4. Shared full-screen workflow shell, slimmed 4 → 3 steps: Start, Skills, Review and publish. Edit uses the shared edit shell with two sections; later versions publish through the shared publish review dialog.

Style: brand primary #0D7C66, DM Sans, 4px / 8px spacing grid, tap targets at least 44 × 44 px, WCAG 2.2 AA contrast. Admin screens: structured density, persistent filters, keyboard-friendly. Coach screens: mobile, one thumb.

Replaces today's design: flat landing table, 4-step wizard, 520px drawer editor, free age-group / skill-level tag pairs, “Core sub-skill” / “Doesn't count” / points fields, three STEP cards on the empty state, and the “Library settings” page.
