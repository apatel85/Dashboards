- **Request:** Ankit (tablet screenshots, 18:16–18:19 ET): table headers not sitting over their figures on several tabs; Lotto "Collapse all" then tapping a card never re-opens it; Daily Brief search box not working; Performance shows "prices as of Invalid Date" / "Updated Invalid Date" and 0.0% returns (BE $209.47 → $201.93 showed −0.0%, GOOGL $293.45 → $298.70 showed +0.0%).
- **Change (Bug 1 — alignment):** root cause was two unlinked alignment markers: headers used `r` (right) while body cells used `num` (mono, no alignment in most table CSS), so Scanner/Performance headers sat right over left-aligned figures and Deep Dive fundamentals headers sat left over right-aligned figures. `src/styles.css` now has one numeric-alignment system for every table class (`dtable`, `mb-table`, `mb-dd-table`, `mb-research-table`, `mb-ref-table`, `ins-table`): `r` and `num` both mean right-aligned on th AND td alike. Header pairing fixed where a header lacked the marker its cells carry: Scanner `#` + Score, Performance Date + Recommended, Congress trades Amount/Disclosed/Traded, Research P(up 30d)/Trigger/Stop, Deep Dive fundamentals numeric columns. Audited all 12 tabs — Congress by-stock, Congress trades (before), Earnings (incl. H/P/C bars, right-aligned via `align-items: flex-end`), Insiders, Research (all-left), Reference, Daily Brief sector table, Deep Dive quotes, Screener, Performance predictions were already paired; Options/News/Admin have no tables.
- **Change (Bug 2 — Lotto collapse):** root cause confirmed in `src/components/Lotto.tsx`: `isOpen = forceOpen ?? open` with the head toggling only local `open`, so after Collapse all set `forceOpen=false` no card could ever open. New shared hook `src/lib/useForceOpen.ts`: the parent passes `{ open, epoch }` (epoch bumps on every Expand/Collapse click) and each card keeps a per-card override that wins over the all-state until the next Expand/Collapse click clears it. Applied identically to Lotto, `src/tabs/Signals.tsx` SignalCard, and `src/tabs/Scanner.tsx` SignalCard (same bug in all three).
- **Change (Bug 3 — Daily Brief search):** the wiring (query state, filter, feed) was correct with filter All — reproduced the failure: with a filter chip other than All/Breakouts active (Options/Congress), typing blanked the whole feed, because `showBreakouts` was false while `showOptions/showCongress/showRest` are all gated on `!q`. Now a non-empty query always shows the breakout results (`showBreakouts` includes `q !== ''`), with the "N matches" count and the no-match empty state.
- **Change (Bug 4 — Performance):** two root causes. (a) Dates: `as_of`/`quotes_as_of` are full ISO timestamps (`2026-11-12T22:57:08.646Z`) but `fmtDate` always appended `T12:00:00Z`, producing an Invalid Date that `toLocaleDateString()` renders literally as "Invalid Date". `src/lib/format.ts` now parses full timestamps directly (bare days unchanged) and returns "—" for anything unparseable, in `fmtDate`/`fmtDateY`/`fmtDayLabel`/`fmtFullDate` — this also fixes the same latent bug everywhere an `as_of` timestamp is formatted (Gamma, Scanner GEX). (b) Percents: `performance.json` stores `pct_change` already in percent units (BE −3.6) but the UI divided by 100 again → −0.0%; the `/100` is removed in all five places (row, Why panel, Avg/Best/Worst stats). The prediction outcomes are the opposite convention — fractions (0.018) — and were passed straight to `fmtPct`, so they also read ±0.0%; new `fmtPctFrac` scales them ×100 (ret_5d/ret_10d/ret_30d, MFE/MAE, modeled_return). Verified against live performance.json: BE −3.6%, GOOGL +1.8%, avg −0.2%, best GOOGL +1.8%, worst BE −3.6%.
