Screen / URL: /memberships/directory → “Add membership” dialog — https://facility-uat.quixeraos.com/memberships/directory

↗ Open this page in the UAT app

Steps to reproduce:

  1. Open /memberships/directory → “Add membership”.
  2. Athlete: QA Test Athlete; Plan: “12 Week — $240.00”; Facility: Cricmax Main Location; Payment: Offline/Cash → submit → toast “Session Pack plan 2 is misconfigured: no credit count”.
  3. Retry with plan “Unlimited test — $20.00” → “Record & assign” → toast “Couldn't add this membership. Please check the details and try again.”
  4. Choose Pay Later → “Assign & bill” → success “Membership assigned — $20.00 outstanding.”

Expected: A failed attempt must not persist a record; the error toast must reflect reality.

Actual: RETEST 2026-10-14 — behavior CHANGED but still wrong. Baseline: the 3 duplicate rows from 2026-10-10 were still there (no backend cleanup). Attempt 1 (12 Week $240, Record & assign): the “Session Pack plan 2 is misconfigured: no credit count” toast still appears and the dialog stayed open; rows stayed at 3 immediately after. Attempt 2 (Unlimited test $20, Record & assign): “Success — Membership added. Receipt RCP-CMX-000081.” and rows went 3 → 5. Two attempts produced +2 rows — consistent with attempt 1's record arriving late (async), i.e. the false-negative persistence STILL reproduces for the 12 Week plan, OR the success path double-created. Either way the count is wrong for what was attempted. ORIGINAL 2026-10-10: all three attempts persisted WITH payment records ($240 cash RCP-CMX-000077, $20 cash RCP-CMX-000078); row actions offer only “View details” — Freeze/Cancel disabled, no delete anywhere, so cleanup needs backend/admin.

💡 Suggested fix: Make membership creation atomic — if validation fails, roll back; never persist on error. The “misconfigured plan” error suggests validation runs after the insert; move validation before any write or wrap in a transaction. Add a uniqueness guard (one active membership per athlete+plan), or at least surface existing memberships in the dialog. Provide an admin delete/void path for bad records.
